## Purpose

Show several students using the Twins configured by different instructors, with a moving view between the overall class structure and individual activity. The focus is on who interacts with which course, what each student receives, how observations persist, and when continuing support is considered.

Provisional scale: two synthetic instructors, one course release per instructor, and four synthetic students, two assigned to each course. These counts keep a one-minute video readable and can change before production.

The visual treatment remains open between a schematic animation and an edited replay of actual runtime traces. The scenario below works for either route, but the evidence labels differ. Do not start an external model experiment merely to populate the animation.

## Cast

| Synthetic role | Configuration / behaviour to show |
| --- | --- |
| Instructor A | Socratic teaching settings; reviewed material and permitted support |
| Instructor B | Explanatory teaching settings; separately reviewed course configuration |
| Student A1 | Asks about a concept and receives an elicitation question |
| Student A2 | Has a separate dialogue and learner record |
| Student B1 | Asks for a rule and receives a source-based explanation |
| Student B2 | Has separate activity; later support is considered only under valid conditions |

Names are synthetic labels. The planned actor assignment is a presentation scenario, not evidence that the historical studies tested this exact two-instructor deployment.

## Proposed 60-second sequence

| Time | View | Action | English caption |
| --- | --- | --- | --- |
| 0–8 s | Wide view of two instructors and two course Twins | Each instructor's approved settings attach to a separate release | Two instructors configure their course Twins |
| 8–16 s | Four students join their assigned course views | Separate conversations and records appear; keep course boundaries visible | Each student has a course-scoped conversation |
| 16–29 s | Move into Student A1's dialogue | Show the saved Socratic example, with the attempt-eliciting question readable | A question invites the student's explanation |
| 29–40 s | Move into Student B1's dialogue | Show the separate saved explanatory example with its source rule | Another dialogue supplies the course rule |
| 40–52 s | Return to the wide view; move the virtual clock forward | Show saved observations feeding later work; highlight one selected delivery or no-delivery event only when its source is selected | Saved activity informs later support |
| 52–60 s | Show instructor controls and the two-course overview | Show review/pause as available controls; retain separate student records | Instructors retain control over continuing support |

Use gentle camera movement and a shared timeline, rather than placing four unreadable full chat windows on screen. The two close-ups are the main reading moments. No simulated mastery percentage or guaranteed improvement is needed.

## Representation and evidence labels

For a schematic version, use a persistent label such as:

> Illustrative multi-course scenario · Synthetic participants

When showing the historical outputs, identify them as saved examples and preserve their history/day information in a legible compact label or source note. If separate traces are combined, describe the film as a composite replay.

For an actual runtime version, seed the synthetic instructors and students in an isolated store, record the exact configuration and revision, capture actual events, and animate those events. Existing multi-history studies alone do not prove that all those actors used the same runtime concurrently.

An animation can place activities side by side for readability. This is not a throughput, concurrency, learning-effect or instructor-fidelity benchmark.

With two students per course, do not invent cohort difficulty statistics that the product would suppress below its five-learner threshold. The instructor view can show configuration and permitted controls; any detailed records must follow the actual product's visibility rules.

## Production route

1. Choose schematic scenario versus actual-event replay; retain this cast and camera structure.
2. Use the two verified saved text examples only within their stated contexts.
3. Select the later-support event before finalizing that segment's captions.
4. Build a time-controlled animation so the video can be re-rendered without manually recording a long session.
5. Inspect a draft for readable English, course/student identity consistency and correspondence to the selected traces.
6. Export an approximately one-minute video for the presentation's demonstration slot.

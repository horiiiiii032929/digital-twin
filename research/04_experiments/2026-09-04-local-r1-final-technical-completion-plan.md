# Local R1 final technical completion plan

## Decision questions

1. Does the qualified Jina v4 late-interaction retriever improve actual-product
   visual answers while preserving boundary safety, citations, source lineage,
   course isolation, latency, and the unchanged text path?
2. Does the explicit synthetic professor profile produce a measurable C2 over
   C1 behavior difference without weakening C1-C3 deterministic hard gates?
3. Can the resulting selected/fallback composition pass one exact local HTTPS
   product qualification?

## Frozen program

`local-r1-final-technical-completion-001` runs two independent checkpoints in
order. `true-visual-product-checkpoint-001` compares text/OCR with the Jina
candidate on 30 answerable and 30 boundary cases. The product sees only course
ID and question; hidden gold opens after all 120 condition responses are
durable. The Jina account ledger imports 144,639 historical tokens, reserves
failed calls conservatively, permits no retry, and never exceeds 10,000,000
tokens.

`professor-fidelity-proxy-c0-c3-002` reuses the immutable 12-case public
synthetic packet. GPT-5.4 Mini generates C0-C3 responses; GPT-5.4 Nano and
GPT-5.4 perform blinded advisory review. Deterministic source, citation, action,
and safety checks run first. Maximum execution is 80 OpenAI calls, two
transport-only retries, and USD 3.

## Finite decisions

- Visual `Keep`: select the release-bound Jina mode for local R1.1.
- Visual `Refine`: retain text/OCR fallback and do not tune the 60 cases.
- Proxy pass: record `completed-go-deeper`; professor approval is still needed.
- Proxy failure: preserve the result and retain the implemented profile workflow.
- Invalid transport/harness execution: preserve evidence and correct only a
  demonstrated operational defect once.

The known 10,000+1,000 package, private Academia Vault, student data, report
writing, durable hosting, real-professor fidelity, and learning-outcome claims
are outside this program.

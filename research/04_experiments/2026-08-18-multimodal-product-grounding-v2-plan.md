# Multimodal product grounding V2 development plan

Date: 2026-08-18

Run ID: `multimodal-product-grounding-v2-development-001`

Status: frozen before implementation and measurement

## Question

Can a deterministic, region-aware offline ingestion path improve retrieval and
citation localization for scanned and mixed-layout course PDFs without adding a
heavyweight vision model to the online student-query path or regressing the
selected text fallback?

## Prediction

Compared with page-bounded selectable text, region-aware extraction with OCR,
table structure, captions, equations, figures, original crops, and explicit
lineage will improve complete visual evidence at rank 3 and atomic recall at
rank 5 on a new public-synthetic development set. The product path should also
preserve citation and permission boundaries. This first deterministic candidate
is not expected to establish production-quality visual descriptions by itself.

## Decision boundary

This run may select the deterministic extraction and citation architecture as a
product foundation. It cannot qualify a vision-description model, establish
performance on private course material, or authorize the historical 24-case
multimodal held-out split. Those cases remain unopened.

## Data

- Dataset: `multimodal-product-grounding-v2-development-1.0.0`.
- Corpus: deterministic public-synthetic PDFs generated by the repository.
- Slices: table, diagram, equation, screenshot, scan, mixed evidence,
  no-evidence, integrity/isolation, and selectable-text control.
- Evidence labels: exact source artifact, page, region kind, bounding box, and
  required atomic facts.
- Sample-size rationale: a small development instrument is sufficient to expose
  parser, lineage, evaluator, and integration defects before model/provider
  qualification. Report raw counts and Wilson intervals; do not generalize from
  the pilot.
- Permissions: synthetic, approved for processing, tutoring, and display.

## Candidates

- `R0-text-page`: existing page-bounded selectable-text representation with
  BM25. Scanned-only pages are unavailable. This is the inspectable control.
- `R1-region-local`: deterministic offline region extraction, injected OCR,
  structured table text, captions, equation/figure regions, and original crop
  references. Query-time retrieval remains text-based and uses BM25 for this
  isolated comparison.
- Product fallback: the already selected text profile, with BM25 rollback. This
  run does not silently replace either profile.

Generated region descriptions are searchable metadata, not authoritative
evidence. No Gemma model is permitted. No external or heavyweight vision model
is used in this run.

## Metrics and hard gates

Metrics are calculated over eligible cases and also reported by slice.

| Measure | Gate for `R1-region-local` |
| --- | --- |
| Complete required evidence@3 | At least 80% and no worse than `R0-text-page` |
| Atomic evidence recall@5 | At least 90% and no worse than control |
| Region nDCG@10 | Greater than control |
| Region localization IoU@1 | Mean at least 0.70 on localized hits |
| Table relationship accuracy | At least 90% |
| Unsupported description rate | 0% in the deterministic candidate |
| No-evidence false-positive rate | At most 5% |
| Course/release/source isolation | 100% |
| Selectable-text control regression | No loss in complete@3 or recall@5 |
| Citation lineage | 100% resolve to approved original page/region/crop |
| Online heavyweight vision calls | 0 |
| Online retrieval p95 | No more than 20% slower than control |

Offline extraction latency, peak memory, crop bytes, region counts, OCR calls,
and parser warnings are recorded without using them as pass/fail gates in this
small pilot. A future real-corpus run must set capacity gates before execution.

Any permission leak, source-version mismatch, citation to generated text rather
than an original region, access to the historical held-out split, or evaluator
failure invalidates the run.

## Method

1. Add first-class region, OCR, description, and crop lineage models behind
   replaceable protocols.
2. Extract selectable text, reading order, columns, tables/cells, figures,
   captions, equation-like blocks, and OCR regions offline.
3. Build release-ready region chunks while retaining the selected text path.
4. Carry page, region, bounding box, checksum, permission, and crop references
   through deterministic citation validation, persistence, API responses, and
   the student source inspector.
5. Generate and validate the new synthetic corpus and labels.
6. Run both frozen candidates over identical questions and compute the metrics
   above from source-linked labels.
7. Record per-case failures as data, parsing, chunking, query, ranking, model,
   policy, integration, evaluator, or operations causes.

## Reproduction

Planned commands:

```text
npm run benchmark:multimodal-product-grounding-development
```

The benchmark command will write ignored detailed output under
`reports/generated/multimodal-product-grounding-v2-development-001/`; the
sanitized summary and machine-readable record will be committed.

## Decision rule

- **Keep** only if every hard gate passes and the architecture has no unresolved
  high-risk defect.
- **Refine** if the path is sound but a repairable quality or operational gate
  fails.
- **Go Deeper** if all pilot gates pass but real-course or model qualification
  is still required before profile selection.
- **Drop** if the candidate regresses the text control, breaks lineage or
  isolation, requires online vision inference, or cannot be reproduced.

The likely successful pilot decision is Go Deeper, not production selection.

## Risks and limitations

- Synthetic layout does not represent the full variability of lecture PDFs.
- Injected deterministic OCR verifies the product boundary but not a production
  OCR engine's quality or licensing.
- Table and equation heuristics may require a qualified layout model later.
- Region-level descriptions remain unqualified until a new model comparison is
  planned and frozen.
- The existing 24-case held-out split remains closed throughout this work.

## Results

Three prospective development attempts are registered. Attempt 001 diagnosed
OCR adapter, table-context, routing, and synthetic-label defects. Attempt 002
passed every quality and lineage gate but failed the frozen relative p95 gate
and exposed two answerable-action abstentions. Attempt 003 corrected those
actions and passed 13/14 gates: complete@3 13/13, atomic recall@5 100%, region
nDCG@10 0.9764, top-1 localization IoU 0.9316, and citation lineage 13/13.
Warm p95 remained 0.053 ms versus 0.023 ms for the page control, above the
frozen 20% relative-overhead gate. The historical held-out split stayed closed.

## Decision

Refine. Retain the region-aware ingestion/citation architecture and selected
text fallback, select no multimodal retrieval profile, and stop tuning the
small development set. Qualify a real OCR/layout provider and representative
end-to-end latency prospectively before any held-out decision.

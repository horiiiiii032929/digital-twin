# AWS demo seed acceptance plan

User requested loading the designed multi-course pack into the deployed Singapore
pilot and receiving professor/student credentials. Compare the existing admin-only
state with the versioned synthetic pilot pack. Reuse authenticated admin and
professor APIs, server ingestion and deterministic publication preflight. Preserve
the existing administrator and selected release. Store generated credentials and
resume mapping privately under ignored output; never put them in evidence logs.

Predict that two ready courses can pass publication gates while the governance
course stays draft. Verify eight account identities, professor ownership, course
and student isolation, real login, source-bound ingestion and persisted release
state. Run representative tutoring through the real service and retain failures;
no human learning claim. Test resumability without password resets or duplicated
courses. Back up first and verify restoration in isolation. Do not email anyone.

Keep the EventBridge office-hours schedule; temporary setup access is allowed,
then stop the server outside hours. Record public verification, local checks,
provider usage if invoked, failure classes and limitations in a named result.

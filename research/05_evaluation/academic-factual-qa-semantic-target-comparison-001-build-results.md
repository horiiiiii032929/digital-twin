# Semantic-target grounding comparison build result

## Decision

`Go Deeper` to one network-free 500-case comparison. No grounding method is
selected by this build checkpoint.

## Question

Can the strongest protocol-valid typed-target baseline be compared fairly with
a semantic target/source-range successor without reusing the three known
development folds or the sealed Program 011 final benchmark?

## Frozen evidence

- Instrument: `academic-factual-qa-semantic-target-comparison-001`
- Dataset: 100 fresh clusters and 500 cases
- Allocation: 25 clusters per course, 400 answerable and 100 boundary cases
- Evidence: 300 minimal canonical source ranges containing 474 exactly
  matchable required references
- Baseline: `typed-target-evidence-v1`
- Candidate: `semantic-target-resolution-v3`
- Operating-systems source: ThinkOS commit
  `5ab731d25042d4aab455566dc7698fdd31373c75`, CC BY-NC-SA 4.0
- Other course sources: ranges excluded if used by any of the three previous
  development packages

Public questions contain no expected action, answer, claim, evidence, or
citation. Hidden gold remains in a separate hash-bound package and is not
loaded during validation or the 20-case simulation.

## Implementation

The candidate parses public semantic targets and requested evidence
cardinality, scopes candidates to approved course/source context, ranks exact
source ranges with deterministic IDF-weighted coverage, clarifies unresolved
cross-range ambiguity, and fails closed when support is incomplete or
unauthorized. It cannot author policy, claims, citations, source versions, or
learner state.

## Verification

- Fresh package is byte-stable and has zero prior source-range overlap.
- 500 normalized questions are unique.
- 474/474 required references are exactly matchable.
- Validation and 20-case network-free simulation pass with hidden gold closed.
- 22 focused tests pass.
- Focused Ruff validation passes.
- Provider calls, tokens, and paid cost: zero.
- Private data and final split access: none.

The complete repository gate is run before the clean execution commit.

## Limits

This build result establishes evaluation readiness only. Extractive,
provider-free responses isolate retrieval, action routing, and source-range
assembly. It does not establish release quality, professor fidelity, real
student usability, learning improvement, or provider-backed autonomy.
